Graphify

将任意文件夹（代码、文档、论文、图片、视频）转换为可导航的知识图谱

1. 基本运行

注意：以下所有 /graphify ... 命令均为 Claude Code Skill 命令，需要在 Claude Code 会话中输入，而非直接在终端 shell 中执行。 
/graphify                    # 分析当前目录
/graphify <path>             # 分析指定路径
/graphify https://github.com/<owner>/<repo>   # 克隆并分析 GitHub 仓库

运行后会生成 graphify-out/ 目录，包含以下输出：

  • graph.html — 交互式图谱（浏览器打开）
  • GRAPH_REPORT.md — 审计报告
  • graph.json — 原始图谱数据

2. 常用选项

选项作用
--mode deep深度提取，生成更多 INFERRED 边
--update增量更新，只重新提取变更的文件
--directed构建有向图（保留边的方向，如 A calls B）
--no-viz跳过 HTML 可视化，只生成报告和 JSON
--svg额外导出 graph.svg（可嵌入 Notion/GitHub）
--graphml导出 graph.graphml（供 Gephi/yEd 使用）
--neo4j生成 Neo4j Cypher 导入文件
--neo4j-push <uri>直接推送到 Neo4j 数据库
--wiki生成可浏览的 wiki（index.md + 每社区一篇文章）
--obsidian生成 Obsidian 知识库
--watch监控文件夹，文件变更时自动重建（代码变更无需 LLM）

3. 查询与分析

/graphify query "这个问题在代码中是如何实现的？"           # BFS 遍历，获取广泛上下文
/graphify query "这个问题" --dfs                           # DFS 遍历，追踪特定路径
/graphify path "AuthModule" "Database"                   # 查找两个概念之间的最短路径
/graphify explain "SwinTransformer"                      # 解释某个节点的含义和关联

4. 添加外部内容

/graphify add <url>                                      # 抓取 URL 并加入语料库
/graphify add <url> --author "Name" --contributor "Name" # 标注作者和贡献者

支持类型：

  • YouTube（自动转录）
  • Twitter/X
  • arXiv
  • PDF
  • 图片（.png/.jpg/.webp）
  • 任意网页（自动转换为 Markdown）

5. 高级用法

跨仓库图谱

同时分析多个仓库并合并为一个图谱：

/graphify https://github.com/owner/repo1 https://github.com/owner/repo2

MCP 服务器

启动 stdio MCP 服务器，供其他 agent 实时查询图谱：

/graphify <path> --mcp

Git 提交钩子

每次 git commit 后自动重建代码图谱：

graphify hook install

CLAUDE.md 集成

让 Claude Code 自动使用图谱，无需手动运行 /graphify：

graphify claude install

6. 成本与缓存

AST 提取（免费）： 代码文件使用抽象语法树提取，完全免费且确定性。
LLM 提取（消耗 token）： 文档、图片等内容使用 LLM 进行语义提取。
  • 提取结果会自动缓存，--update 时只处理变更文件
  • 如果设置了 GEMINI_API_KEY，会自动使用 Gemini 进行语义提取，大幅节省成本

7. 快速开始示例

# 分析当前项目
/graphify .

# 分析一个 GitHub 仓库（含特定分支）
/graphify https://github.com/owner/repo --branch main --mode deep

# 增量更新（修改代码后）
/graphify . --update

# 查询图谱
/graphify query "认证模块如何与数据库交互？"
